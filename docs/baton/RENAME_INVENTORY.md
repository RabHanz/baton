# Baton to Tessaya rename: inventory and plan

Order from the Director (2026-11-03): the product is Tessaya, and "in many places it still says Baton.
Even the repo's name is still Baton. All the services and scripts, everywhere." This is phase 1 of five:
a count and a decision per kind of name. No code changes here. D71 (persisted and wire names keep their
old spelling) is the rule for anything stored or already shipped.

Counts are case-insensitive `git grep -o baton` on `main` at e0af09aa83, text files only: **8,122
occurrences in 718 files**, against 859 of `tessaya`. Tracked file paths containing `baton`: 1,251.

Decisions: **now** = rename in the phase named; **shim** = rename, and the old name keeps working;
**keep** = never rename, one-line reason.

## Order and merge rules

Each phase is one PR, merged only when `verify` and `baton-ci` are both green. Rows 9 and 10 touch
the files that every other open branch touches: they go last, after the open baton/* PRs land, and
the manager is told before they open. `patches.sh verify` and `vp run check:changed` run before every push.

## What will not change, and why (one line each)

- appId, AUMI, install dir, userData, login item: the update path (row 16).
- `fabric_*` tables, `fabric.*` wire, `baton*.json` and `.ndjson` user-data files: live data and installed clients (D71, rows 11 to 13).
- Release tag format and the `baton-ci` required check: renamed only with the repo and ruleset edits (rows 8, 18).
